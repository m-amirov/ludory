# Connect Yandex C5 Build and Browser Acceptance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate a new Yandex-only Ludory game, build a reproducible non-release candidate ZIP, and verify real Runtime/Connect integration in desktop and emulated mobile browsers without claiming live Yandex acceptance.

**Architecture:** Add an opt-in Studio template with a locally bundled Ludory Runtime + Yandex Connect entrypoint; load the official SDK only from the host's `/sdk.js`. A separate build-time packager admits only safe game files and emits a deterministic candidate archive; existing Runtime/Phaser and browser test harnesses exercise the generated game with a test-only SDK fixture. Live Console checks require a separate owner action.

**Tech Stack:** Node.js >=22, ESM, esbuild 0.25.12 (existing), Studio catalog/scaffold, `node:test`, Playwright 1.56.1 (existing browser harness), `fflate` as a pinned **build-time-only** dev dependency for portable deterministic ZIP creation, existing `@ludory/runtime`, `@ludory/runtime-phaser`, and `@ludory/connect-yandex` C1–C4.

**Spec:** `docs/superpowers/specs/2026-10-29-connect-yandex-design.md` §§3, 8–10; `docs/superpowers/specs/2026-10-30-ludory-v1-completion-design.md` F2. Platform docs: `https://yandex.ru/dev/games/doc/ru/sdk/sdk-about.html`, `sdk-game-events`, `sdk-events`, `sdk-player`, `sdk-adv`, `console/debug-panel` (rechecked 2026-10-31).

## Global Constraints

- This C5 branch starts at `main` merge `0814d02880c8afdec863dae22a06f93d53551e3c` (PR #50), in `.worktrees/connect-yandex-c5`. Do not modify concurrent F1 worktrees or frozen games/CEOS/Starter Kit.
- `@ludory/core` must remain platform-neutral. Do not change generic `runtime-basic` or blend Yandex and VK SDK entrypoints. New template targets **only** `yandex-games`.
- Production `index.html` has one blocking `<script src="/sdk.js"></script>` in `<head>`, before the game module; no bundled/copied SDK and no absolute Yandex service-storage SDK URL. Test fixtures serve a fake `/sdk.js` without shipping it.
- SDK initialization is explicit (`createYandexConnector`), and `LoadingAPI.ready()` occurs only after `host.initialize()` and asset readiness; actual RUNNING/PAUSED states drive GameplayAPI. Manual pause uses `lifecycle.setManualPaused` and is never overridden by platform resume.
- Player storage uses only `createYandexPlayerStorage` as an explicit choice; no silent localStorage fallback, implicit login, account-data collection, automatic ads, or reward without same-attempt `onRewarded`.
- Candidate archive is **not** a production release or rights certification; immutable file/hash evidence, content filtering, and no overwrite are required. Real Yandex Console draft/upload, ad inventory, physical devices, publication and moderation are separate owner-authorized gates.
- Mock browser results report `SDK_CONTRACT_PASS` and `YANDEX_LIVE_NOT_RUN`, never `YANDEX_LIVE_PASS`/`RELEASE_READY`. CI and local tests must retain failures and blockers honestly.

## File Structure

- `packages/studio/catalog/profiles/web-game.json`: opt-in template registration.
- `packages/studio/catalog/templates/yandex-runtime/{template.json,index.html,src/main.js,assets/ludory-yandex.js}`: new self-contained starter (built asset committed, not a copy of Yandex SDK).
- `scripts/build-yandex-template.mjs`: deterministic esbuild exports, with `--check` comparing generated bytes to committed asset.
- `scripts/build-yandex-candidate.mjs`: build-time candidate ZIP, manifest inspection, path/target/content safety, exclusive output write and deterministic byte/hash reporting.
- `packages/studio/test/yandex-template.test.mjs`: Studio scaffold, bundle and negative template tests.
- `packages/studio/test/yandex-candidate.test.mjs`: archive/reproducibility/exclusion and tampering tests.
- `packages/runtime/test/browser/yandex-c5-smoke.mjs`: desktop/mobile generated-candidate browser fixture using **real generated files** and fake `/sdk.js`.
- `packages/runtime-phaser/test/browser/yandex-c5-phaser-smoke.mjs`: optional real Phaser renderer attached to the Yandex C2 lifecycle and host.
- `.github/workflows/runtime-browser.yml`, browser test scripts, root `package.json`/lock and `packages/connect-yandex/README.md`: CI, smoke gates, operator usage and explicit live blockers.

## Review Focus

1. **SDK script missing or load error:** production game must expose blocked/error state and never call `LoadingAPI.ready` or pretend gameplay started — Task 1 test and Task 3 browser negative case.
2. **Stale/tampered or foreign-platform package input:** fail before archive creation for wrong target, altered required SDK tag, symlink, unexpected `sdk.js`, or VK SDK payload; preserve source and any existing destination — Task 2 tests.
3. **Platform resume during manual pause or advertisement:** preserve pause ownership and audio suspend without false GameplayAPI.start — Task 3 test.
4. **Guest/cloud save refusal or corrupt save:** show cloud error, never local fallback and never restore corrupt state — Task 3 test.
5. **Reproducibility and browser evidence inflation:** identical inputs produce byte-identical candidate archives, while fake SDK and emulated devices cannot set `YANDEX_LIVE_PASS` — Tasks 2 and 5 tests.

### Task 2: Reproducible and non-destructive Yandex candidate archive

**Files:** Create `scripts/build-yandex-candidate.mjs`, `packages/studio/test/yandex-candidate.test.mjs`; modify root `package.json`, `package-lock.json` for the pinned build-only ZIP library. No Release status or archive upload integration.

**Interfaces:** Export `buildYandexCandidate({ projectDir, outputZip }): Promise<{ archivePath: string, sha256: string, files: { path: string, sha256: string, size: number }[] }>` and expose `node scripts/build-yandex-candidate.mjs --project <path> --output <new.zip>`. Require a Studio-created `yandex-runtime` project with exactly `['yandex-games']` and a valid source-bound manifest/receipt, but permit authored modifications to the game source/assets (do not require clean Git). Archive only `index.html`, `ludory.project.json`, `src/main.js`, `assets/ludory-yandex.js` and safe regular game asset files under `assets/` (approved media extensions; no extra JS/SDK or dev tests). Exclude Studio metadata, `.codex-os`, CEOS evidence, local saves, rights source folders, secrets, Git and test fixtures. Validate every candidate path with `lstat` (no symlinks), case-insensitive duplicates, safe bounds/regular-file types, SDK tag and Yandex-only API; reject a copied `/sdk.js` or VK bridge. Use sorted entries, fixed ZIP timestamps/metadata and a fixed compression strategy, report source SHA-256 and ZIP SHA-256. Refuse an existing `outputZip`, including symlink; create exclusively and clean up **only owned partial bytes**, never a replaced or user-edited file. Output must be outside the project root.
